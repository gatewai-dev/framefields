# framefields-styles

A video's direction is four parts, each a short file in this skill:

- **Look**: what it looks like (palette, type, texture, motion character, grade, and art direction for generated media).
- **Format**: where it plays (size, fps, length, safe areas, cut rhythm).
- **Genre**: what kind of video it is (the beats, what the audio does, what's on screen).
- **Medium**: where the pixels come from (code-drawn, 3D, footage, AI-generated). A film can use several. Media are decided per piece: by the user when they say, otherwise by you from the request.

A **preset** names a good combination of a look, a format and a genre.

## Choosing

1. If the user named a preset or parts, use them.
2. Otherwise, infer the format (from the platform or length they mention) and the genre (from what the video is for), then offer two or three looks that pair well, by name and one line each. Ask only what you can't infer.
3. Pick the media from what the request needs (say which), unless the user named them.
4. Read only the files you use: one look, one format, one genre, and each medium.

## Combining

Each part writes only in its own area, so they combine without overriding each other. When two pull against each other:

- **Format** wins on the frame: size, safe areas, length, how often to cut.
- **Genre** wins on structure: the order of the beats, what the audio does.
- **Look** wins on everything visual: color, type, texture, easing, grade.
- **Medium** wins on production: tools, scripts, cost, verification.

A slow look in a short format keeps its visuals with fewer elements; it does not slow the format down. `clashes` in a part's frontmatter mark pairs to handle with care, never pairs to refuse.

From code, `framefields/styles` has the same library: `combineStyles({ look, format, genre, media? })` returns the brief these rules produce, `styleClashes(mix)` the pairs to watch, and `styleLibrary` every part.

## Generated media matches the look

When a medium uses AI generation, it generates images (video only if the user asks), and every prompt ends with the look's `ai.direction` and `ai.avoid`, word for word; the engine then moves the stills the way the look's `ai.motion` says. The look's grade then goes over generated and drawn material alike (`comp.apply`). That shared text and grade are what make generated images and code-drawn type read as one film. The steps are in [media/ai-generated.md](media/ai-generated.md).

## Adding a part

One markdown file in its kind's folder, named by its id. Frontmatter holds the facts (see an existing file of the same kind); the body has only that kind's `##` sections, in order:

- look: Look, Type, Motion, Grade?, Build it with, Avoid?
- format: Frame, Timing, Safe areas?, Build it with?
- genre: Beats, Audio, On screen, Build it with?
- medium: Pipeline, Cost?, Consistency?, Verify, Build it with?
- preset: Note? (only)

Names in backticks under "Build it with" must be real `framefields` exports or `components/<id>` registry items; the tests check them. Run `pnpm run sync:style-library` after any change.
