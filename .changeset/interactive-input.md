Interactive compositions. `comp.input` is live input for games, simulators and agents: keys, pointer, wheel and gamepads, latched once per frame before the frame's hooks (`down`, `pressed`, `released`, `axis`, `pointer`, `wheel`, `gamepads`, and as signals), events as they arrive (`input.on("pointerdown", …)`), and feeding in code for agents and tests. Picking is measured by the renderer from its ground-truth targets: `e.pick()`, `input.pick(x, y)` and `comp.pick(x, y, { frame })` give the 3D layer under a pixel, the surface point and normal, and rays from the same camera (`rayPlane` intersects them). The preview player feeds `comp.input` from the page when the composition uses it and answers picks on the next frame it draws. `Physics.steel` worlds take commands at any time (`setJointTarget`, `setBodyPose`, `setBodyTwist`, `setBodyWrench`) and `world.draggable(comp.input)` lets the pointer drag bodies on Steel's spring (`grab`, `moveGrab`, `release`, `bodyOfLayer`, `toSteel`, `toScene`). Live text: `Layer.text` takes a function of the frame (`(ctx) => string`) or a `Signal<string>`, and `rich` takes functions as runs, read each frame the text is drawn, so scores, timers and status lines follow game state in the player. The preview serves fonts from the same folders the export reads them from (a parent's `assets/fonts`, `FONTS_DIR`), so pages in a monorepo draw text.
